# WASI 0.2 toolchain smoke fixtures

The Component text inputs under `src/` are parsed and validated by pinned
`bytecodealliance/wasm-tools v1.260.0`. The generator workflow verifies the
upstream release asset SHA-256 and records the exact WASI 0.2.8 source commits
used by TurboWasm's retained descriptors.

Normal tests do **not** download wasm-tools and do **not** fetch the network.
The workflow-generated bytes are checked in as
`generated/wasi02_toolchain_fixtures.h`; the generator regenerates that header
and byte-compares it with the checked-in copy, so source/toolchain drift fails
fast.

Corpus coverage:

- `monotonic-clock.wat`: clocks provider execution;
- `random-u64.wat`: random provider execution;
- `cli-exit.wat`: CLI exit control flow;
- `filesystem-preopens.wat`: descriptor resource + canonical list/string
  memory + resource drop;
- `stream-poll-block.wat`: CLI stdin producer → input stream subscribe →
  pollable block → resource drop;
- `socket-instance-network.wat`: `wasi:sockets/instance-network@0.2.8`
  → nominal `network` resource → canonical resource drop.

The public corpus test executes the checked-in corpus through `TurboWasm::WASI02`. A
separate internal resume test drives the same stream/poll Component through
Runtime host-wait yield/completion/resume so the blocking path is not reduced
to a ready-only smoke.
